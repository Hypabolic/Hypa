# Hypa 1.0.0

Hypa 1.0.0 adds a terminal multiplexer for coding agents.
You run agents in panes, attach from any terminal, and share a session with another machine.

## Highlights

### Mux and attach

- A local mux server owns your panes. `hypa` attaches to it.
  A closed terminal does not stop the panes. Attach again to continue.
- Ghostty is the only VT engine. The mux paints one composed frame for the host terminal.
- Tabs, splits, a sidebar, a goto picker, a workspace switcher, copy mode with search, and popups.
- Settings, 19 built-in themes, a first-run onboarding overlay, and custom command keybindings.
- The host terminal palette, focus events, mouse, and bracketed paste reach the panes.
  Attach clients now receive the application cursor and bracketed paste modes.
  Arrow, Home, and End keys use the form that the running program asks for.
- Narrow and mobile layouts.

### Agent runtime

- Agents create, read, and drive panes through a documented runtime protocol.
- Hidden panes: an agent runs work in a pane that does not take a layout slot.
  A person can show, hide, and read those panes from the attach view.
- `hypa` commands target the calling pane and can wait for output.
- Every pane gets `HYPA_BIN_PATH`.
  See `docs/guides/pane-environment.md`.
- Detection finds agents that run behind wrapper and symlinked processes.

### Agent skill and integrations

- `hypa integration install` installs the runtime skill and the integration for each agent that Hypa detects.
  The first run lists every file that it writes and asks before it writes.
- The skill teaches when and how an agent uses background panes.
  See `docs/guides/agent-skill.md` and `docs/guides/background-panes.md`.

### Share and connect

- Share a session with another machine. The share dialog makes an invite.
  The invite carries every reachable address of the host, so a person does not set an address first.
  The client tries each address in turn and reports the address that answered.
  See `docs/guides/share-invite.md`.
- QUIC is the first path. TCP with TLS is the fallback.
  A certificate pin protects every connection.
  The secret goes only after the pin matches.
- A cube is a saved peer. Connect moves your view to that peer and keeps the destination shell.
- `hypa connectivity accept` reports why QUIC did not start.
  A specific bind address does not start QUIC. See `docs/guides/connectivity-accept.md`.

### Client app

- A native Linux client and an Avalonia client, built with Native AOT.

## Platforms

- Linux and macOS are the mux hosts.
  Release archives cover `linux-x64`, `linux-arm64`, `osx-x64`, and `osx-arm64`.
- Windows is not a mux host. Release archives contain no Windows mux.
  See `docs/ADRs/0015-windows-is-not-a-mux-host.md`.

## Upgrade notes

- A running mux keeps the binary that started it.
  After you upgrade, stop the old mux and start it again.
- A certificate file that an earlier version wrote still loads.
  New certificate files use an ECDSA P-256 key.
- An invite with one host still redeems.
  A new invite holds at most 32 addresses.
  Name one address with `--advertise-host` to choose a different one.

## Known limits

- An IPv6 address in an invite needs a listener that serves IPv6. Bind to `::` to serve both families.
- QUIC does not start when you bind the accept helper to a specific address. That accept uses TCP with TLS.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
