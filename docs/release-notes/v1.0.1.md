# Hypa 1.0.1

Hypa 1.0.1 makes the mux installable through Homebrew, npm, and PyPI, and fixes a hang at startup on macOS.

## Highlights

### Install with a package manager

Hypa 1.0.0 shipped only as a GitHub release and an install script.
The npm, PyPI, and Homebrew packages stayed at 0.1.15, and they did not carry the mux.
Each release now publishes to all three.

```bash
brew install hypabolic/tap/hypa
npm install --global @hypabolic/hypa
pipx install hypa
```

- Every channel installs the same release archive that `install.sh` installs.
  `hypa` finds the mux host, the attach client, the PTY helper, and the Ghostty library next to itself.
- The packages cover Linux (glibc 2.34 or newer) and macOS 12 or newer, on x64 and arm64.
- Wheel tags now match the binaries, so `pip` no longer installs a wheel on a system that cannot run it.
- npm and PyPI launchers repair a missing execute bit on the helper programs.

### Update

- `hypa update` finds Homebrew, npm, pnpm, pip, pipx, and uv installs.
  It prints the matching upgrade command, for example `brew upgrade hypa` or `pipx upgrade hypa`.
- A package manager that owns the binary now takes precedence over an old `~/.hypa/install.json`
  from an earlier script install.
  Before, `hypa update` could aim at the wrong copy.

### Fixes

- `hypa --version` and every other command no longer spin forever when macOS denies `mach-lookup`.
  That is the rule that `brew test` and agent sandboxes use.
  The default host watched `appsettings.json` for changes, and that watcher cannot start in such a sandbox.
  Hypa ships no `appsettings.json`, so the mux host, `hypa serve`, and the CLI no longer watch it.
- The Homebrew formula declares the correct license, `FSL-1.1-ALv2`.

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host. The npm and PyPI packages have no Windows build.
  The 0.1.x Windows npm packages stay on the registry and are not updated.

## Upgrade notes

- A running mux keeps the binary that started it.
  After you upgrade, run `hypa mux stop`, then `hypa attach`.
- If you installed with `install.sh`, `hypa update` upgrades in place as before.
  If you switch to a package manager, remove the script install first, so that only one `hypa` is on your `PATH`.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
