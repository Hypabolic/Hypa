# Hypa 1.0.2

Hypa 1.0.2 fixes a crash on macOS when you open a new workspace, a startup failure on Linux machines with a `002` umask, and a crash in sandboxes that cannot list a parent directory.
The install script now offers your package manager.

## Highlights

### Fixes

- **macOS: pressing "new" in the workspaces panel could crash Hypa with a segmentation fault.**
  Hypa starts the attach client and the mux by replacing its own process image.
  On macOS, that leaves the signal that the .NET runtime uses to pause threads for garbage collection in a state the runtime does not expect.
  The first pause then jumped to address 0.
  It could land anywhere, in the attach client or in the mux, which made the crash look random.
  Hypa now resets signal handling when it starts those programs, and does the same for detached custom commands.
  We saw the crash on macOS 27.0.1 with the 10.0.12 runtime.
  The runtime fixed this upstream in dotnet/runtime#132581, in 10.0.13, which is not yet released.
- **Linux: the mux now starts when the umask is `002`.**
  That is the Ubuntu default with user-private groups.
  Before, `hypa` failed with "Mux server did not become ready", and no `mux.log` existed to explain why.
  The runtime directory is now created with mode `0700`.
  If an existing directory is group-writable, Hypa says so and prints `chmod 700 '<dir>'`.
  When the mux exits without writing a log, the error now names `hypa mux serve --session <name>` instead of a missing file.
- **`hypa --version` and every other command no longer crash when a parent directory cannot be listed.**
  Project root detection listed each parent directory and failed with `UnauthorizedAccessException`.
  That happens in sandboxes such as `brew test` on Linux, where `/` cannot be listed.
  A directory that cannot be listed now counts as having no project marker.

### Install

- `install.sh` offers Homebrew, npm, pipx, or uv when they are available, and installs directly by default.
  Press Enter to keep the old behavior.
  The prompt also works with `curl | sh`.
- If the `hypa` on your `PATH` belongs to a package manager, the script prints the upgrade command and asks before it installs a second copy.
  A run with no terminal stops with exit code 1 in that case.
- `--via script|brew|npm|pipx|uv` or `HYPA_INSTALL_METHOD` skips the prompt.
- The README now documents every install channel.

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- A running mux keeps the binary that started it.
  After you upgrade, run `hypa mux stop`, then `hypa attach`.
  Until you do, the mux keeps the old signal handling.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
