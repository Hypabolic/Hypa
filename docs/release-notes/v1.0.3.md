# Hypa 1.0.3

Hypa 1.0.3 fixes pasting into `hypa attach`, keeps the workspaces panel in step with the directory you are working in, and fixes `hypa attach` after an upgrade from a release that left a group-writable runtime directory.

## Highlights

### Fixes

- **Multi-line pastes no longer run line by line inside `hypa attach`.**
  The attach client never enabled bracketed paste on your terminal, so every newline in a paste ran as Enter in shells and coding agents.
  A pasted control byte could also trigger a Hypa keybinding; for example, a pasted ctrl+b entered prefix mode.
  Attach now enables bracketed paste and restores your terminal on detach.
  Pasted text bypasses keybindings and goes to the pane, wrapped in paste markers only when the program in the pane asked for them, as tmux does.
  Prompts, pickers, and copy mode still receive a paste as typed keys.
- **Large pastes no longer lose input or detach the client.**
  Pasting more than a few hundred characters could print an `input backpressure` error and deliver only part of the text, or drop you back to your shell.
  The client now waits for space instead of dropping input, and the mux bounds pane input by bytes rather than by count.
  A 2 MiB paste arrives intact.
- **The workspaces panel now follows the directory you navigate to.**
  The workspace path, repository name, branch, and dirty marker update as you `cd`, switch repositories, or leave Git.
  Each workspace takes its directory from the first pane of its first tab, not from whichever pane has focus, so splitting or switching tabs does not change it.
  If that pane closes, the next remaining pane takes over.
  Names you set yourself are kept; generated names follow the directory.
  The mux reads the directory from the shell's OSC 7 reports, or from the shell process on Linux and macOS, and resolves Git status itself.
- **`hypa attach` works again after upgrading from a release that left a group-writable runtime directory.**
  Releases before 1.0.2 could create `~/.config/hypa/runtime/<session>` with mode `0775` when the umask was `002`.
  Attach then refused to start with "Socket parent ... is writable by group or others".
  Hypa now changes its own runtime directory to `0700` when you own it.
  It still refuses a custom `HYPA_RUNTIME_SOCKET` parent, a directory another user owns, and shared directories such as `/tmp`.
- **`hypa -c` keeps a word with quoted parts as one argument.**
  `hypa -c "printf '[%s]\n' --flag='(a|b)'"` passed `--flag=` and `(a|b)` as two arguments, where a shell passes one.
  `hypa -c` and the `hypa_shell` tool now join the parts of a word as a shell does.
- **Pi no longer warns at startup when it loads `@hypabolic/pi-hypa`.**
  The package now declares `@earendil-works/pi-tui` as a peer dependency, as Pi requires for packages it provides.

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- A running mux keeps the binary that started it.
  After you upgrade, run `hypa mux stop`, then `hypa attach`.
  Until you do, the workspaces panel does not follow your directory.
- The session database gains two columns when the new mux first starts.
  The migration is automatic.
  Existing workspace names that match their directory become generated names and follow the directory; any other name is kept as yours.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
