# Hypa 1.0.5

Hypa 1.0.5 keeps your local machine in the cubes list, so you can always switch back to it after connecting to a remote cube.

## Highlights

### Fixes

- **The local machine always appears in the cubes section.**
  It is now listed first, under the machine's name, from the first launch.
  Previously, it was listed only if a local placement had been registered by hand.
  On most installs the section showed "No cubes" until you added a remote cube, and then listed only that remote.
  After you connected to the remote, there was no entry to click to get back to your own machine.
  A local placement you registered yourself is still used as-is and is not listed twice.

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- No configuration changes are needed. Cubes you have already added are kept.
- After upgrading, close and reopen the attach client to see the local cube.
  A running mux keeps the binary that started it; run `hypa mux stop`, then `hypa attach`, to restart it with the new version.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
