# Hypa 1.0.6

Hypa 1.0.6 detects a mux that is still running from an install an upgrade removed, explains why its new panes fail, and restarts it onto the new version in one step.

## Highlights

### Features

- **The sidebar offers to restart a mux left over from an upgrade.**
  When the local mux runs from a removed install, a **↻ restart to update** row appears at the top of the sidebar.
  Click it and confirm, and attach stops the mux, starts it from the installed Hypa, and reattaches on the new version.
  The row is not shown while you view a remote cube, because a restart would act on the local mux.
- **New `hypa mux restart` command.**
  It stops the mux and starts it from the installed version. It asks first; without a terminal, pass `--yes`.
  It targets the mux named by `--session` or `--socket`.
  It refuses to run inside the mux it would restart, because stopping that mux would close the shell running the command.
- **Attach warns before connecting to a stale mux.**
  On a terminal, attach explains that the mux is running from the old install and asks `Continue? [y/N]`.
  Non-interactive and `--once` attaches print a warning with the `hypa mux restart` command.
- **`hypa status` shows client and server versions.**
  New lines: `client.version`, `server.version`, `server.install_present` and `server.stale`.

### Fixes

- **New tabs and panes on a stale mux now explain the failure.**
  Previously, after a package upgrade removed the install directory, every new tab or pane failed with the generic "child/provider start failure".
  The error now names the version the mux is running and how to restart it.
- **`hypa update` ends with the restart step to run.**
  It points at the sidebar row or `hypa mux restart` instead of "Please restart hypa."

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- No configuration changes are needed.
- A mux started by 1.0.5 or earlier does not report its version, so 1.0.6 counts it as stale.
  On your first attach after upgrading, accept the restart prompt, or run `hypa mux restart` from a terminal outside Hypa.
  A restart closes every pane.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
