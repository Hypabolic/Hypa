# Hypa 1.0.7

Hypa 1.0.7 keeps cube sharing available when an attach closes and restores it after mux restarts. It also fixes reconnecting to a rebooted peer, Escape leaking into shared panes, and QUIC being disabled on Linuxbrew installs.

## Highlights

### Fixes

- **Cube sharing keeps running after you close or detach the attach that started it.**
  The mux now owns the share listener, so paired peers stay connected while your panes keep running.
  Any attach on the same mux can see the running share and stop it.
  Sharing resumes after a mux restart or upgrade, using the same certificate so saved peers keep their pin.
  If the listener fails, the mux retries automatically; the share dialog shows the error while it retries.
  The dialog also reports when share settings could not be saved, so you know whether sharing will resume after a restart.
  ([#141](https://github.com/Hypabolic/Hypa/pull/141))
- **Clicking a cube reconnects after its peer reboots or its connection closes.**
  Previously, a selected cube could remain marked as connected and clicking it did nothing, leaving a frozen view.
  Hypa now checks that the connection is live before reusing it and dials the peer again when needed.
  ([#142](https://github.com/Hypabolic/Hypa/pull/142))
- **Escape closes dialogs without reaching the pane underneath.**
  A lone Escape released after an input pause now follows the same dialog and menu routing as other keys.
  This fixes dialogs that would not close and shared-shell input that could lose its first character after Escape leaked through.
  ([#142](https://github.com/Hypabolic/Hypa/pull/142))
- **QUIC works on Linuxbrew installs whose group-writable directory is private to its owner.**
  Previously, these installs fell back to TLS over TCP because the integrity check rejected all group write permissions.
  On Linux, the check now permits the owner's private primary group when the system's account sources can be verified as local.
  Shared groups and directories writable by other users remain rejected.
  ([#140](https://github.com/Hypabolic/Hypa/pull/140))

### Maintenance

- Make activation-pump wake tests independent of runner scheduling delays and fix a macOS Unix-socket test failure.
  ([#143](https://github.com/Hypabolic/Hypa/pull/143), [#144](https://github.com/Hypabolic/Hypa/pull/144))

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- After upgrading, restart the local mux to enable mux-owned sharing.
  Use the sidebar's **↻ restart to update** action, or run `hypa mux restart` from a terminal outside Hypa.
  A restart closes every pane and disconnects active peers.
- If sharing was enabled before upgrading, start it again in the share dialog after the restart.
  From then on, sharing resumes automatically when that mux session restarts, unless you press **stop**.
  Hypa stores the sharing settings in `share.json` beside the session socket; no manual configuration migration is required.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
