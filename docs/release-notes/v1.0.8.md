# Hypa 1.0.8

Hypa 1.0.8 fixes panes that froze when another window or a cube peer was viewing them, and agents that appeared signed out inside Hypa panes. The in-app "what's new" overlay now shows these release notes instead of placeholder text.

## Highlights

### Fixes

- **Your own window keeps working while a cube peer drives your panes.**
  Previously, when a peer connected to your shared cube, your local window could stop repainting and reject your typing, then close.
  The peer's connection was mistaken for your own window reconnecting, because both used the same per-mux connection number.
  Each window now identifies itself to other cubes with its own stable id.
  ([#149](https://github.com/Hypabolic/Hypa/pull/149))
- **A pane keeps updating when another window viewing it has a different size.**
  The pane follows the size of the window that drives it; other windows now show it clipped or padded to fit, instead of freezing.
  This happened with two local windows of different sizes as well as with a cube peer.
  ([#148](https://github.com/Hypabolic/Hypa/pull/148))
- **Agents started in a Hypa pane see the same sign-in as a normal terminal.**
  Panes now receive the standard login-session variables, including `USER`, `LOGNAME`, `SHELL`, `TMPDIR`, `SSH_AUTH_SOCK` and the `XDG_*` directories.
  This fixes Claude Code and other agents reporting that you are signed out, and restores SSH agent access in panes, for example for `git push` over SSH.
  Secret-like variables are still not passed to panes.
  ([#146](https://github.com/Hypabolic/Hypa/pull/146))
- **"What's new" shows the real release notes.**
  Previously, it showed the same placeholder text after every upgrade.
  ([#147](https://github.com/Hypabolic/Hypa/pull/147))

## Platforms

- Linux and macOS, on x64 and arm64.
- Windows is not a mux host.

## Upgrade notes

- Restart the local mux after upgrading so new panes get the login-session environment.
  Use the sidebar's **↻ restart to update** action, or run `hypa mux restart` from a terminal outside Hypa.
  A restart closes every pane and disconnects active peers.
- The cube freeze fix needs only one of the two machines on 1.0.8, so it also works with peers that have not upgraded yet.
- If you installed with a package manager, upgrade with `brew upgrade hypa`, `npm install --global @hypabolic/hypa`, or `pipx upgrade hypa`.
  If you installed with `install.sh`, `hypa update` upgrades in place.

Report a fault at https://github.com/Hypabolic/Hypa/issues.
